# 设计说明：从 Fact Graph 到 Modeling Evidence Graph

## Danus 中保留的五条原则

1. 主控只负责全局规划，局部搜索交给工作者。
2. 验证器冷启动、无状态，并拥有真相层唯一写权限。
3. 已验证事实进入带依赖边的内容寻址 DAG。
4. 错误事实撤销时，所有依赖事实级联失效。
5. 目标验证后才成文，成文结果再次验证。

## 针对数学建模的扩展

数学证明的核心对象是命题；数学建模的可信度是异构链：

```text
题意 → 数据 → 假设 → 模型 → 代码 → 实验 → 结果 → 决策 → 叙事
```

因此本 Harness 的真相层不是单一 fact，而是 typed evidence。节点既记录自然语言
statement，也记录 artifact、哈希、依赖、检查命令和审核时间。模型推导正确但数据
泄漏，或代码正确但决策过度外推，都能沿图定位并撤销。

## 双循环

- 研究循环：候选 → 检验 → 反例 → 修订 → verified。
- 交付循环：证据图 → 叙事包 → 论文 → 逐句复核 → 修订。

两个循环共享同一证据图，因此论文不能创造研究阶段不存在的确定性。

## 论文叙事逻辑

高质量 Agent 论文通常不是“我们先做 A，再做 B”，而是：

1. 现有范式在哪个结构性瓶颈失败；
2. 新系统提出什么最小机制；
3. 机制为何理论上/工程上有效；
4. 哪组实验把机制贡献与规模收益分离；
5. 失败案例揭示什么边界。

这里将其映射为建模论文的“决策问题—信息困难—模型机制—可信度链—行动建议—
适用边界”。它既保留竞赛论文需要的完整数学细节，也避免把正文写成实验日志。
